# Vibe Coding 时程序员最想要什么 —— 第一性原理分析

## 分析方法论

从"程序员坐在电脑前打开 AI 编程工具"这个第一性场景出发，逐步推导核心需求。

## 第一性场景

程序员打开工具 → 有一个想法/任务 → 用自然语言描述 → AI 开始工作 → 程序员观察/等待/干预 → 得到结果 → 验证/调整 → 循环

## 第一层：不可约减的痛点（vibe coding 的真实摩擦）

### 痛点 1: 看不见（Observability）
> "AI 在干什么？它改了什么文件？它的思路是什么？"

当 AI 在后台跑 5 分钟改 10 个文件时，程序员是**盲的**。当前 newbee 的 WebUI 
只有一个对话流 — 模型输出和工具调用混在一起。程序员想知道的是：
- 它现在在改哪个文件？（**当前焦点**）
- 它总共改了哪些文件？改动量多大？（**影响面**）
- 它执行了什么命令？成功还是失败？（**执行轨迹**）

**这不是"对话"能解决的 — 需要独立的、结构化的状态面板。**

### 痛点 2: 控不住（Controllability）
> "我想让它停下来/换个方向/撤销刚才的操作"

当前 WebUI 有"中断"按钮，但中断之后呢？程序员需要：
- **steering**: 不用等 AI 跑完就能插入新指令（"别改那个文件"）
- **undo/redo**: 一键回退到上一个好状态
- **scope control**: 限制 AI 只能动某些文件/目录

### 痛点 3: 等得焦虑（Progress & Feedback）
> "它还要多久？是不是卡了？"

AI 跑一个长任务时，程序员看着光标闪烁，不知道是在思考还是死了。需要：
- **live 进度指示**：当前在第几步、在做什么类型的操作
- **token/时间消耗实时显示**：让人对成本有感知
- **"心跳"信号**：证明 AI 还活着

### 痛点 4: 上下文丢失（Context Loss）
> "它忘了我们之前讨论的那个约束"

长对话后 compaction 会丢失细节。程序员需要：
- **持久的目标/约束板**：不受 compaction 影响
- **文件锚定**：明确告诉 AI "这个文件很重要，别乱改"

### 痛点 5: 审查困难（Review）
> "它改了 500 行代码，我怎么审查？"

当前只能看 inline diff。程序员需要：
- **session 级 diff 汇总**：本次会话所有文件改动的统一视图
- **按文件分组**：每个文件的 diff 可以折叠/展开
- **快速跳转**：从 diff 直接跳到源文件

## 第二层：从痛点推导功能优先级

用第一性原理排序：**频率 × 痛感 × 实现成本**

| 痛点 | 频率 | 痛感 | 当前状态 | 优先级 |
|------|------|------|---------|--------|
| 看不见（文件追踪） | 每次会话 | ★★★★★ | 无 | P0 |
| 等得焦虑（进度） | 每次长任务 | ★★★★ | 有 token 计数 | P0 |
| 审查困难（diff 汇总） | 每次会话结束 | ★★★★ | 只有 inline | P1 |
| 控不住（steering） | 偶尔但关键 | ★★★★ | 只有中断 | P1 |
| 上下文丢失 | 长会话 | ★★★ | 有 compaction | P2 |

## 第三层：newbee 的差异化优势

newbee 有 DEE（持久 Elixir 环境）、EventBus、Session 管理、WebSocket 推送。
这意味着它可以做到其他工具做不到的：

1. **实时文件追踪**：evaluator 执行的每个 Fs.write / Edit.patch 都产生事件
   → WebSocket 推到前端 → 实时显示"AI 正在修改 xxx.ex"

2. **真实进度**：不像其他工具只有"thinking..."，newbee 有 step 计数、
   tool call 历史、token 消耗——全部可以 live 展示

3. **环境感知**：newbee 知道项目的 git 状态、文件结构、test 结果
   → 可以在 UI 上直接展示项目级状态

## 结论：设计方向

**"Mission Control" 面板** — 在现有对话流旁边，加一个可折叠的右侧/底部面板：
1. **文件变更追踪器**（实时显示 AI 改了哪些文件、diff 统计）
2. **执行时间线**（step-by-step 的工具调用历史，可折叠）
3. **Session Diff 汇总**（一键查看所有变更的 unified diff）

这不只是 UI 改进——它改变了程序员和 AI 的信任关系：
从"盲信"到"看得见、能干预"。
